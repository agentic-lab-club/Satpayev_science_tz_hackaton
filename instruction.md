# Инструкция для LLM: Генерация синтетических данных (ТЗ и Метки)

## 📌 Контекст и задача
Вы — AI-эксперт по формированию датасетов. Ваша задача — генерировать синтетические примеры **Технических заданий (ТЗ) на научно-исследовательские работы (НИР)** и присваивать им соответствующие **метки (оценки)** по официальной шкале (scorecard).

Эти данные будут использоваться для обучения и тестирования моделей проверки качества ТЗ.

---

## 📊 Описание меток (Labels / Scorecard)

Синтезируемые ТЗ необходимо размечать по следующим критериям (в сумме 100 баллов). Ваша задача — задавать баллы и короткое обоснование (reasoning) для каждого критерия.

1. **`strategic_relevance` (Стратегическая релевантность) — max 20 баллов**
   - *Что оценивается:* Соответствие гос. программам, запросам индустрии, национальным приоритетам.
   - *Высокий балл (15-20):* Четко указана связь с нац. проектами, решает актуальную проблему отрасли.
   - *Низкий балл (0-7):* Связь с потребностями рынка или государства не описана.

2. **`goals_and_tasks` (Цели и задачи) — max 10 баллов**
   - *Что оценивается:* Конкретность, измеримость (SMART), соответствие задач поставленной цели.
   - *Высокий балл (8-10):* Цель измерима, задачи детализированы и логичны.
   - *Низкий балл (0-4):* Формулировки расплывчаты ("исследовать сферу", "улучшить показатели").

3. **`scientific_novelty` (Научная новизна) — max 15 баллов**
   - *Что оценивается:* Оригинальность предлагаемого решения по сравнению с мировыми аналогами.
   - *Высокий балл (12-15):* Предлагаются принципиально новые методы, архитектуры, формулы или патенты.
   - *Низкий балл (0-5):* Использование стандартных, давно известных подходов без адаптации.

4. **`practical_applicability` (Практическая применимость) — max 20 баллов**
   - *Что оценивается:* Готовность к внедрению (УГТ / TRL), наличие потенциального заказчика, возможность масштабирования.
   - *Высокий балл (15-20):* Понятный путь до MVP и коммерциализации.
   - *Низкий балл (0-7):* Сугубо фундаментальное исследование без понятного применения.

5. **`expected_results` (Ожидаемые результаты) — max 15 баллов**
   - *Что оценивается:* Измеримые KPI (кол-во статей, патенты, конкретные метрики системы - точность >95% и т.д.).
   - *Высокий балл (12-15):* Четкие метрики, которые можно проверить (числовые значения).
   - *Низкий балл (0-5):* Абстрактные фразы ("будет разработана методика", "повысится эффективность").

6. **`socio_economic_effect` (Социально-экономический эффект) — max 10 баллов**
   - *Что оценивается:* Создание рабочих мест, импортозамещение, экологический эффект, снижение издержек.

7. **`feasibility` (Осуществимость) — max 10 баллов**
   - *Что оценивается:* Адекватность сроков, бюджета и задействованных ресурсов (команды).

## 🛠 Формат генерации (System Prompt Output)

Генерируй данные в формате JSON, где есть раздел с "ТЗ" (вводные данные) и "Evaluation" (выходные метки модели). Текст ТЗ должен строго следовать официальному шаблону, включающему пункты: «Общие сведения», «Цели и задачи», «Стратегические документы», «Ожидаемые результаты (Прямые и Конечные)» и «Предельная сумма программы».

```json
{
  "document_text": "1. Общие сведения:\n1.1. Наименование приоритета...\n1.2. Наименование направления...\n\n2. Цели и задачи программы\n2.1. Цель...\n2.2. Задачи...\n\n3. Какие пункты стратегических документов решает...\n\n4. Ожидаемые результаты\n4.1 Прямые результаты...\n4.2 Конечный результат...\n\n5. Предельная сумма программы...",
  "labels": {
    "strategic_relevance": { "score": 18, "reasoning": "..." },
    "goals_and_tasks": { "score": 8, "reasoning": "..." },
    "scientific_novelty": { "score": 14, "reasoning": "..." },
    "practical_applicability": { "score": 15, "reasoning": "..." },
    "expected_results": { "score": 12, "reasoning": "..." },
    "socio_economic_effect": { "score": 8, "reasoning": "..." },
    "feasibility": { "score": 9, "reasoning": "..." }
  },
  "overall_quality": "High" // High / Medium / Low
}
```

## 🧩 Примеры для Few-Shot Prompting

### Пример 1. Хорошо проработанное ТЗ (High Quality)

**Текст ТЗ (выдержка):**
> **1. Общие сведения:**
> 1.1. Наименование приоритета: Информационные, коммуникационные и космические технологии.
> 1.2. Наименование специализированного направления: Искусственный интеллект в индустрии.
> 
> **2. Цели и задачи программы:**
> 2.1. Цель: Создать ML-модель для предсказания износа бурового оборудования с точностью не менее 92% за 7 дней до инцидента.
> 2.2. Задачи: 1) Сбор данных вибрации; 2) Обучение ансамбля трансформеров для условий -40℃.
> 
> **3. Стратегические документы:**
> Решает пункты 4.1.2 и 4.1.3 Государственной программы «Цифровой Казахстан» (снижение потерь и цифровизация промышленности).
> 
> **4. Ожидаемые результаты:**
> 4.1 Прямые: 1 патент на алгоритм, ПО уровня TRL-6, 2 статьи в журналах Q1.
> 4.2 Конечные (эффект): Снижение внеплановых простоев на 15%, снижение экономических издержек отрасли.
> 
> **5. Предельная сумма:**
> 150 000 тыс. тенге на 3 года.

**Метки (Labels):**
- `strategic_relevance`: **19/20** (Прямая отсылка к цифровизации и снижение потерь)
- `goals_and_tasks`: **10/10** (Цель максимально конкретна: точность 92%, горизонт 7 дней)
- `scientific_novelty`: **14/15** (Указана уникальность метода: трансформеры для низкочастотных вибраций)
- `practical_applicability`: **18/20** (Достижение TRL-6, ясное применение)
- `expected_results`: **14/15** (Измеримые KPI: 1 патент, минус 15% простоев)
- `socio_economic_effect`: **8/10** (Снижение экономических издержек отрасли)
- `feasibility`: **9/10** (Реалистичное сочетание методов и TRL)

### Пример 2. Слабое, "водянистое" ТЗ (Low Quality)

**Текст ТЗ (выдержка):**
> **1. Общие сведения:**
> 1.1. Наименование приоритета: Исследование и программирование.
> 1.2. Наименование направления: Улучшение работы предприятий.
> 
> **2. Цели и задачи программы:**
> 2.1. Цель: Написать хорошую программу, которая будет работать быстро и без ошибок.
> 2.2. Задачи: 1) Проанализировать сферу; 2) Улучшить показатели работы компьютеров.
> 
> **3. Стратегические документы:**
> Потому что в наше время программирование помогает автоматизировать работу.
> 
> **4. Ожидаемые результаты:**
> 4.1 Прямые: Будет создана программа с новыми версиями языков программирования, отчет на 50 страниц.
> 4.2 Конечные: Сотрудникам станет удобнее работать.
> 
> **5. Предельная сумма:**
> 100 000 тыс. тенге.

**Метки (Labels):**
- `strategic_relevance`: **3/20** (Нет связи с программами, нет описания проблемы, общие слова)
- `goals_and_tasks`: **2/10** (Неизмеримая цель "работать быстро и без ошибок")
- `scientific_novelty`: **1/15** (Использование новых версий языков не является научной новизной)
- `practical_applicability`: **4/20** (Непонятно, где и как это будет внедряться)
- `expected_results`: **3/15** (Измерим только "отчет на 50 страниц", остальное абстрактно)
- `socio_economic_effect`: **2/10** (Абстрактное "станет удобнее", нет оценки эффекта)
- `feasibility`: **3/10** (Без конкретики невозможно оценить реализуемость)

## 🚀 Правила генерации для модели:
1. Вариативность: Генерируйте ТЗ из разных областей: IT, медицина, агропромышленность, материаловедение.
2. Баланс классов: Создавайте примеры как с очень высокими баллами, так и средние/плохие примеры со смешанными оценками (например, хорошая новизна, но ужасные KPI).
3. Избегайте шаблонов: Не используйте одни и те же фразы для хороших примеров; варьируйте структуру и язык документа (формальный, академический, технический).
